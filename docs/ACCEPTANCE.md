# Initial acceptance register

These are **planned acceptance requirements, not implemented tests**. Every product requirement starts `NOT_RUN`: no product verification has been performed. Documentation validation for M00-T01 does not satisfy these entries. This initial register does not claim full requirements coverage or security certification; M01 must refine traceability, finite supported cases, measurable thresholds and evidence obligations before affected capabilities can be accepted.

Stable requirement IDs must not be reused for different requirements. Milestone IDs refer to the canonical names in [ROADMAP](ROADMAP.md); the product boundary is in [PRODUCT](PRODUCT.md), and actual progress is in [STATUS](STATUS.md). Evidence below is expected future evidence, not an assertion that an artifact exists. Evidence containing customer data or credentials belongs in approved private storage, with safe references only in repository records.

All entries also depend on future implementation and designated human review. A blocking condition names a missing prerequisite; it does not change the initial verification status from `NOT_RUN`. Later execution may record `PASS`, `FAIL` or `BLOCKED` with revision, scope, evidence reference and reviewer decision. A passing check alone does not accept a milestone. M12 accepts only its restricted AWS scope; M21 needs full agreed release evidence.
